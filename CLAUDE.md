# Правила роботи над проєктом teacher-journal

Дипломний проєкт: приватний десктопний електронний журнал для викладачки математики і фізики.
Спілкування з автором — українською; питання до автора — у форматі варіантів відповідей.

## Архітектура (не порушувати)
- Python + PySide6 (UI), PostgreSQL + SQLAlchemy 2 + Alembic.
- Три шари: `ui` → `services` → `repositories`. UI не імпортує `sqlalchemy`, `journal.models`, `journal.repositories`.
  Єдиний дозволений дотик UI до БД — `journal.db.session_scope()` для відкриття транзакції навколо виклику сервісу.
- Сервіси отримують `Session` ззовні; транзакції — через `journal.db.session_scope()`.
- Зміни схеми БД — лише через міграції Alembic.
- Кольори інтерфейсу — лише через токени в `src/journal/ui/theme.py`.

## Дані та безпека
- Реальні дані учнів, `.env`, дампи БД ніколи не комітяться.
- Паролі — лише хеш Argon2. Паролі й токени ніколи не з'являються в коді, логах чи чаті.
- Тести працюють лише з окремою базою `TEST_DATABASE_URL` (journal_test), у транзакції з відкатом.

## Розподіл роботи
- Рутинне (установки, шаблонний код, прості CRUD, тести) — агенти на легших моделях (Haiku/Sonnet).
- Архітектура, схема БД, складна логіка, дизайн і перевірка коду агентів — основна модель.
- Після кожного етапу — звіт «🔍 Контроль»: що перевірено і з яким результатом.

## Git і GitHub
- Кожен етап — окрема гілка (`feature/...`, `fix/...`, `chore/...`) і PR у `main`. У `main` напряму не комітимо.
- Перед злиттям: `pytest` зелений, застосунок запускається.
- **Рецензія Fable.** Кожен PR перед злиттям незалежно перевіряє агент на моделі Fable 5.2:
  коректність, безпека, витік даних/секретів, тести, дотримання архітектури.
  Вердикт `APPROVE` → PR зливається (merge commit), гілка видаляється, автор отримує короткий звіт.
  Вердикт `REQUEST_CHANGES` → виправлення і повторна рецензія; після 2 невдалих кіл — питаємо автора.
  Автор дозволив зливати PR за схваленням Fable без додаткового підтвердження.
- **Fable ухвалює важливі рішення по проєкту** (обсяг етапу, дизайн, UX, тексти) — за дорученням автора.
  Автора не відволікаємо: робота йде у фоні, без відкриття вікон на його екрані (UI перевіряється offscreen).
  Правки викладачки, коли вони з'являться, мають пріоритет над рішеннями Fable.
- Завжди питати автора (Fable цього не вирішує): зробити репозиторій публічним, видалити репозиторій
  чи дані, force-push або переписування історії, додати співавторів, будь-що з правами адміністратора
  чи паролями, а також послаблення правил безпеки й рецензії в цьому файлі
  (агент і рецензент не можуть самі послабити процес).
