# Stage 8b — Finish the installer

*Fable spec, 2026-11-15. Branch `feature/stage-8b-installer`, one PR. Builds on the pilot
(`docs/specs/stage-8-pilot.md`, PR #18) and the deferred review findings of PRs #18, #21, #23.*

## 0. Decisions
- A. **Version.** `0.9.0` (release candidate for the teacher's trial) in one place
  (`pyproject.toml`); `installer.iss` and the app's About/title read it (build script passes it
  to ISCC via `/DAppVersion=`; the app reads it via `importlib.metadata` with a fallback constant).
- B. **One running copy.** `QLockFile` in the data root (`<data root>\app.lock`). A second launch
  shows «Програма вже відкрита.» and exits without touching the DB or the embedded server.
  This removes the "second instance stops the first one's server" problem.
- C. **Server ownership.** `EmbeddedDb.stop()` stops the server only if this process started it
  (`started_by_us`), also on the error path.
- D. **Upgrade over an existing install.** Same `AppId` → in-place upgrade into the same folder.
  Inno: `AppMutex` (named mutex created by the app at start, e.g. `TeacherJournal-Running`) +
  `CloseApplications=yes`; before files are replaced and in `[UninstallRun]`, run
  `{app}\pgsql\bin\pg_ctl.exe stop -m fast -D <data>` if a server from this install is running
  (helper: `TeacherJournal.exe --stop-server`, which knows the data path rules; hidden, no window).
  Data folder is never touched. First start after upgrade → before-migration backup (already
  implemented) → `alembic upgrade head`.
- E. **Robustness (from PR #18 review).**
  1. ProgramData fallback: `icacls` by full path (`%SystemRoot%\System32\icacls.exe`); non-zero exit →
     `EmbeddedDbError` (fail closed). Test.
  2. `--smoke` refuses to run when not in bundled mode («SMOKE FAIL not bundled», exit 1).
  3. Wrap `psycopg` errors, `subprocess.TimeoutExpired` and Alembic errors from startup in
     `EmbeddedDbError` with a clear Ukrainian message (details only in the log).
  4. Empty `db.secret` next to an initialised cluster → the same "restore db.secret" error, never a
     silent new password.
  5. `pg_ctl start` timeout 60 s; on a non-zero exit re-check `pg_ctl status` once before failing.
  6. Uninstall message text: say the data folder is kept, without naming a path that may be wrong
     (or show the real one via a `[Code]` call to the helper).
  7. Tests that call `resolve_layout()` must not depend on real 8.3 names (`fake_ascii` / explicit
     fallback). Add coverage for `ensure_running` reuse/missing-secret branches, `running_port`, `stop`.
  8. `build.ps1`: compute the system site-packages path only when needed (no throw without system
     Python); copy PostgreSQL's licence file into `pgsql\` and the installer.
- F. **Polish.**
  - Icon: a simple original icon (open notebook / grade mark) generated by
    `packaging/make_icon.py` with PySide6 (QPainter → multi-size `.ico`: 16–256 px), committed as
    `packaging/icon.ico`; used by the exe (PyInstaller `icon=`), the installer (`SetupIconFile`),
    shortcuts and the window (`QApplication.setWindowIcon`).
  - Installer: Ukrainian texts, publisher = project name (no personal data), optional desktop
    shortcut, «Запустити програму» at the end (skipped in silent mode).
  - Backups backlog: soften the «журнал виглядатиме порожнім» text; one-time notice when a
    restore marker's copy folder stays unavailable; log tracebacks without exception messages in
    export/backup UI handlers (privacy + diagnosability).
- G. **Not in scope.** Code signing (no certificate; README explains the SmartScreen prompt),
  auto-update, second Windows account test (documented as a manual check).

## 1. Acceptance (all offscreen / silent, nothing on the author's screen)
1. Unit tests for B, C, E1–E5, E7 and the `--stop-server` helper; full `pytest` green.
2. Build from a clean worktree: `packaging/build.ps1` → `dist\TeacherJournal-Setup.exe`.
3. Silent install into a scratch folder with a scratch `JOURNAL_DATA_DIR` → `--smoke` OK →
   create data (smoke may insert a marker row via a test-only flag, or reuse the DB) → silent
   **upgrade** with a rebuilt installer of a bumped test version → `--smoke` OK, data kept, a
   `before-migration` copy exists only if the revision changed → silent uninstall → data kept,
   no `postgres.exe` from the scratch install left running.
4. Second-instance check with `--smoke`-style headless run: second process exits with the
   «already open» code while the first holds the lock.
5. Report: sizes, cold/warm start times, anything that did not work.
